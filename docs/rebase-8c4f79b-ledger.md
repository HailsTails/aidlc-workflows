## How a path is routed

- **replaced**: one of the two thin entries (`scripts/package.ts`, `scripts/agent-knowledge.ts`), or a path present at `B` and absent at `965cbec73`. The receiving owner comes from the retired file's kind:
  - `manifest.ts` goes to the host's `distribution.ts` and `host-data.ts`.
  - `emit.ts` goes to the host's `projection/`.
  - `onboarding.fills.ts` goes to the host's `onboarding-fills.ts`.
  - `biome.json` goes to `lint/biome-successor.ts` and the monolith-lines ratchet.
- **outside-build**: `docs/`, `tests/`, `.github/`, and the root files `CHANGELOG.md`, `README.md`, `zensical.toml`, `AGENTS.md` and `CONTRIBUTING.md`.
- **retained**: everything else. Its owner is:
  - the core module itself, when `src/bridge-map.json` lists it, with the src files that read it (**dual-use**);
  - otherwise `core`, `plugins`, or the harness's shipped asset or authored runtime file.

A commit is **retained**, **replaced**, **mixed** (both) or **outside-build** from its paths.

**At head** compares the path on `study/foundation-8c4f79b` with `8c4f79b4b`. It reads one of:

- **upstream bytes**;
- **upstream bytes plus foundation's unchanged delta**: foundation had already changed the file before the rebase, and its change against `8c4f79b4b` is the same as it was against `caea995ae`;
- **differs from upstream**;
- **absent**.

A commit needs a judgement when any of these holds:

- it is replaced or mixed;
- it touches a dual-use core module, a legacy script under `scripts/`, or a build file added in the range;
- it touches a conflicted path;
- it touches a path that differs from upstream or is absent at head.

**Bridged reads touched** lists each export a bridge reader imports from the module that appears in the commit's changed lines or hunk headers. It is a deliberately wide text match:

**Conflicted** is per path. It marks every commit touching one of the 25 paths that conflicted when `965cbec73` merged `8c4f79b4b` (`git merge-tree --write-tree --name-only --no-messages -X no-renames`).
